# ectool — 短剧成片流水线

把**母版封面 + 原片 + 字幕 + BGM** 一次编码合成为成片：

- 封面作为**视频第 1 帧**（平台缩略图直接取它），集数按文件名自动识别并渲进封面
- 字幕烧进画面（SRT → ASS，样式可从剪映预设读取）
- 片尾**定格 1 秒 + 撞击音效 + 星火特效**
- BGM 混入，音量按**每集人声响度实测**自动定，并做侧链闪避

全程**单次编码**，无中间代；**零 npm 依赖**，只要 `ffmpeg` / `ffprobe` 和 Node ≥ 18。

```bash
node bin/ectool.js make ./我的剧集/
```

---

## 快速开始

素材丢进一个文件夹即可，无需配置文件：

```
我的剧集/
├── cover.jpg                  # 封面（名字含 封面/cover/poster/竖版，或取最大的图）
├── 第1集_xxx.mp4              # 原片
├── 第2集_xxx.mp4
├── ep1_en.srt                 # 字幕（文件名能认出集数即可）
├── ep2_en.srt
├── 第1集bgm(悬疑).mp3          # BGM（名字含 bgm/音乐/配乐）
└── 片尾音效.mp3                # 可选
```

也支持分子目录（`原片/`、`字幕/`、`bgm/`）。

```bash
node bin/ectool.js pick ./我的剧集/    # 拖框定集数位置 → 写入该文件夹的 preset.json
node bin/ectool.js make ./我的剧集/    # 出片 → 成片/ + report.json
```

## 命令

| 命令 | 说明 |
|---|---|
| `make <文件夹>` | 一键出片，自动识别素材，无需配置文件 |
| `pick <文件夹>` | 拖框器：可视化调集数位置/字体/颜色，**预览是 ffmpeg 真渲染** |
| `plan -c <config>` | 只看识别与配对结果，不写文件 |
| `run -c <config>` | 按配置文件批量执行 |
| `preview -c <config> -e N` | 渲染单张封面 |

## 配置的三层

```
内置默认  →  ~/.ectool/defaults.json（跨剧通用）  →  <剧文件夹>/preset.json（本剧专用）
```

见 `config.example.json`。

## 素材命名约定

**集数是唯一的连接键**——文件名里能认出集数就行，视频/字幕/BGM 用同一套规则（`第N集` / `SxxExx` / `EP12` / `[08]` / 分隔符包围的数字…），并自动屏蔽 `4K`/`1080p`/年份 等干扰 token。

推荐字幕用 `EP01.srt` 形式。一集匹配到多个候选时按确定性规则排序取第一个，**不会停下来问人**，选择结果写进 `report.json`。

## 全自动与可追查

没有人工闸门。所有歧义按规则消解，每个决策落到 `成片/report.json`：用了哪个字幕、哪条 BGM（及理由）、增益多少、人声响度实测值、裁了几帧黑尾、走哪条编码路径、耗时。

`成片/.ectool-manifest.json` 记录每个产物的**配置指纹 + 源文件 mtime + 字幕/BGM 路径**。任何一项变了下次自动重渲，不会因"输出已存在"静默跳过。

## 产物校验

每个产物自动校验，任一项不过就回退或报错（并删除残留）：

- 尺寸、SAR 与源一致；帧数恰好 +1（+片尾帧数）
- 首帧是关键帧（IDR）；**封面帧真的占满预期时长**
- **流内分辨率无突变**（容器头正常但帧尺寸中途变化，是拼接失败的典型症状）
- 首帧内容与封面一致（灰度签名比对）
- **字幕真的渲上去了**（libass 字体没匹配上时是静默失败，退出码仍为 0）
- BGM 混入检测（按预期抬升量自适应；电平过低时如实记为"无法校验"而非判失败）

## 踩过的坑（都已处理，列出来供参考）

**`concat` 流拷贝在带 edit list / B 帧的源上会静默产出坏文件。** 首帧 `duration` 被压成 1 tick（0.08ms，等于不可见），而容器头、帧数、首帧内容比对**全部正常**。真实导出的成品多半带 `start_time != 0`，所以 Path A（快路径）会自动跳过这类源。

**`concat` 会丢弃旋转矩阵。** rotate=90 的源拼接后容器头写 1080×1920、实际编码帧却是 1920×1080，流内分辨率突变。

**`blend=screen` 必须在 RGB 空间做。** 在 yuv420p 上跑会把色度平面一起 screen，整片洋红。

**ASS 的 `Fontsize` 不是 em 像素。** libass 沿用 VSFilter 约定按字体度量缩放，且不同字体系数不同（实测思源黑体 0.712 / Metropolis 0.781）。本工具在运行时实测标定，不写死系数。

**剪映按文种分字体。** 预设里的 `font_path` 只记了一支（如 `zh-hans.ttf`），渲英文字幕实际走 `en.ttf`（Metropolis）。

**剪映即使关掉阴影/背景也会写满默认值。** 必须看 `has_shadow` / `background_style` 开关位，不能看 `shadow_alpha` 有没有值。

**`alimiter` 拦不住鼓击类瞬态。** 设 `limit=0.97` 实测输出仍到 1.32，加 `latency=true` 也无效。改用浮点峰值归一化。

**`volumedetect` 的读数比真实浮点峰值低约 2dB**（它在整型格式上测），不能用来算增益。

**`ass` 滤镜不认 `-ss` 偏移**，烧字幕必须在完整时间轴上做。

## 依赖

- `ffmpeg` / `ffprobe`，需编译进 `libass`、`libfreetype`、`libx264`
- Node.js ≥ 18
- 星火特效可用内置程序化粒子（无需素材），或指向任意黑底 PNG 序列
